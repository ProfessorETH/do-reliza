# Мастерская персонажей

Первый пилот — Мира из верхнего левого портрета игрового атласа. Это отдельный арт-прототип; он ещё не заменяет персонажа в демоверсии.

Просмотр на действующем сервере: http://127.0.0.1:5179/art/hunyuan/preview.html. При запуске другого статического HTTP-сервера из корня проекта путь остаётся `/art/hunyuan/preview.html`. В готовый архив демо папка `art/` намеренно не входит.

- `mira/mira-review-v2.glb` — модель для просмотра: 47 994 треугольника, два материала, около 1.6 MB.
- `mira/mira-review-v2.blend` — редактируемая коллекция `Mira_Review_Asset` с упакованной текстурой. Её можно открыть отдельно или добавить в рабочую сцену через Append.
- `mira/reference-front-v1.png` — целевой образ в полный рост; это сгенерированный референс, не рендер готовой модели.
- `mira/review-qc.json` — фактические размеры, контакт с полом, топология, хеш результата и незавершённые этапы.
- `mira/shape-v1.api.json`, `shape-v1.receipt.json` — воспроизводимый граф локального Hunyuan3D 2.1 и идентификатор выполненного задания.
- `mira/mira-paint-v1-views/` — исходные шесть пар ракурсов albedo / metallic-roughness, сгенерированные локальным Paint. На `reference-back-repair-v1.png` убран случайный рисунок на спине.

## Как получен результат

1. Imagegen подготовил фронтальный референс по игровому портрету с разрешения пользователя. Промпт — в `mira/REFERENCE.md`.
2. Второй ПК `192.168.3.38:8000`: Hunyuan3D 2.1, 30 шагов, фиксированный seed, 4096 latent tokens, octree 384. Проверены настоящая очередь, схема и отсутствие ручного запрета второму ПК. Официальный шаблон адаптирован к уже установленным отдельным загрузчикам модели, vision encoder и VAE.
3. Проверка в Blender через действующий MCP. Очищены оторванные фрагменты; сетка пересобрана и уменьшена до 48 тысяч треугольников. `cleanup_mira.py` выполняется внутри Blender после импорта сырого GLB в коллекцию пилота.
4. На основном ПК установлен локальный Hunyuan Paint, но активные MCP-серверы не предоставляют его локальные узлы. Поэтому `run_local_paint.py` вызывает существующий Python API пакета без установки серверов и без изменения его кода. Веса использованы офлайн из имеющегося кэша. Для собственного процесса установлен лимит PyTorch 14 GiB; чужие процессы не выгружались и не останавливались.
5. Paint успешно сгенерировал 6 ракурсов, но его OpenCV-экспорт не записал PNG по кириллическому пути. Ракурсы сохранены; `resume_local_bake.py` восстановил только UV-запекание через временную ASCII-папку. Diffusion повторно не запускался. Квитанция первоначальной ошибки сохранена отдельно от успешного восстановления.
6. Во втором варианте использована более гладкая сетка и исправленный задний ракурс. В Blender сварены вершины на UV-швах, поправлены нормали, убраны металлические свойства ткани и кожи. Волосам назначен медный материал вместо цветовых артефактов. Три микроскопических вырожденных участка после OBJ-конверсии очищены с повторной проверкой: 0 открытых и 0 неманифолдных рёбер. Рост 1.72 m, нижняя точка стоп на z=0.
7. GLB экспортирован с JPEG-текстурой качества 92; BLEND сохраняет редактируемую модель и упакованный источник текстуры. Рабочий файл офиса не перезаписывался.

Промежуточные тяжёлые версии сохранены локально в игнорируемой папке `work/hunyuan-mira-intermediates/`; перечень и хеши — в `mira/intermediate-archive.json`. Ключевой сырой результат, исходные ракурсы, референсы, финальный BLEND/GLB и квитанции хранятся в Git. Локальные логи и лишние копии текстур не отправляются в репозиторий.

## Что ещё нужно для игры

Модель годится для оценки внешности. Лицо, пряди волос и пальцы пока мягче и менее аккуратны, чем в референсе. Подробная мимика, скелет, веса деформации, ходьба, посадка и работа ещё не сделаны для этого персонажа. Старые игровые модели сохраняют работающие анимации.

Следующая проверка — один полный цикл на Мире: скелет → веса плеч, кистей, бёдер и коленей → шаг без скольжения → контакт с креслом → клавиатура и мышь. Только после этого заменять `assets/models/mira.glb` и переносить процесс на остальных пятерых.

Наполнение игры описано отдельно в `planning/OFFICE-LIFE.md`: энергия, понятные причины настроения, перерывы, магазин за отдельные очки обустройства и ограниченное число событий. Это дизайн, не реализованные механики.
