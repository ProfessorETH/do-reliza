# Портретные головы v4

Авторитетный источник внешности — шесть портретов из `assets/agents.png`.
Точные кропы находятся в `references/*-portrait.png`. Нейтральные фронтальные
референсы `*-head-front-v1.png` созданы отдельно для реконструкции; они помогают
построению, но не заменяют исходные портреты при художественном сравнении.

Для каждого героя выполнена отдельная локальная реконструкция Hunyuan3D 2.1
на secondary `192.168.3.38:8000`: 4096 latent tokens,40 steps, CFG5, octree512.
Полные API-графы, prompt_id, настройки и пути сырых результатов сохранены рядом
с персонажами в `shape-a.*`. Исходные многомиллионные сетки остаются локально
в игнорируемых `raw/`; новые задания для повторного просмотра не нужны.

## Этапы

1. `clean_shape.py`: сварка дублей, пересчёт нормалей, слабое сглаживание и
   decimate до60тыс. треугольников. Отчёт отдельно отмечает незамкнутые края
   волос; сетки не объявляются герметичными.
2. Установленный Hunyuan Paint API, `art/hunyuan/run_local_paint.py`:6ракурсов
   по512px,15steps, CFG3, текстура2048. GPU primary; только один Paint-процесс.
   Comfy MCP не предоставляет Paint-узел, поэтому используется установленный
   API без нового сервера. Шесть результатов albedo и MR сохранены локально.
3. `landmarks.json`: вручную измеренные радужки и линия закрытых губ в Paint
   и фронтальном референсе. `front_anchor.py` решает трёхточечное аффинное
   соответствие и запекает видимую переднюю часть в Blender на CPU.
   Обратная сторона и скрытые поверхности используют яркость многовидовой
   текстуры с отдельными палитрами кожи и волос, чтобы убрать оранжевую заливку.
   Кожа у границы лица отвергает тёмный силуэт волос фронтального референса.
   У Норда и Эхо уши исключены из маски волос по измеренным координатам.
4. `bake_normals.py`: перенос рельефа исходной головы на облегченную сетку
   в tangent normal. `scripts/optimize-head-normal.js` упаковывает карту в
   RGB PNG1024 со strength0.35; геометрия, UV и albedo сохраняются.
5. `scripts/attach-portrait-head.js`: новая сетка крепится к существующей
   кости `Skin_<id>_Head`; старые голова, фотоплоскость и глаза скрываются.
   Тела, bind matrices и пять исходных клипов сохраняются. Исходный BIN v3
   остаётся дословным префиксом файла; сжатый JSON позволяет восстановить v3
   через `recoverPortraitBase()` даже в новом clone без рабочей папки автора.

`head-detailed.glb` — отдельная голова с материалом. `assembled/<id>.glb` —
проверяемый персонаж целиком. После проверки эти файлы переносятся в
`assets/models/`. `team-portrait-v4.blend` — упакованный источник новой версии;
`team-rigged-v3.blend` сохранён без изменений.

В игре используется небольшой локальный morph моргания; глаза не являются
свободно вращающимися отдельными объектами. Полного лицевого рига, речи и
липсинка в этой версии нет. По одному фронтальному портрету нельзя подтвердить
точное сходство затылка и профиля: эти части восстановлены приблизительно.
Волосы остаются стилизованной статичной геометрией без физики прядей.

## Проверка и повторная сборка

Галерея: `/art/characters/preview.html` — портрет рядом с3D, фронт,¾, профиль,
затылок, крупный план и пять движений. `?portrait=4` открывает рабочие экспорты
из `review-manifest.json`. Основная игра читает только `assets/models/`.

Перед повторным Paint сначала проверять receipt: генерация не повторяется
из-за сбоя экспорта. У Pixel первая запись завершилась ошибкой cp1251 при
печати китайского сообщения уже после сохранения GLB; готовый файл восстановлен
из указанного staging, повторной diffusion не было. Локальный runner теперь
переключает свои потоки в UTF-8 и сохраняет staging до экспорта.

После правок: `npm run check`, `npm test`, `npm run build`, `npm run test:hosting`.
Тесты сравнивают бинарные данные тела, скелета и клипов с восстановленной v3,
загружают реальные GLB и проверяют крепление, посадку, маршруты и моргание.
