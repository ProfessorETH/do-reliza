# Демо 0.5: запуск и размещение

Игра статическая: серверная логика, аккаунты и платные API не нужны. Для просмотра нужен HTTP(S), а не двойной клик по index.html.

План отдельного сервера, ограничения по ресурсам, требования устройств и порядок выпуска — [planning/HOSTING.md](planning/HOSTING.md). Ресурсы «Братиков» для игры не использовать. Домен покупает пользователь.

После `npm run build` выполнить `node scripts/prepare-hosting.js`: он создаёт проверенные gzip-копии и локальный receipt `dist/hosting-report.json`. Шаблон Caddy находится в `deploy/Caddyfile`; `GAME_ADDRESS` — отдельный домен, `GAME_ROOT` — абсолютный каталог релиза/current. Загружать только `dist/demo-v05`, receipt хранить отдельно. Кэшу требуется повторная проверка (`no-cache`), поскольку имена ресурсов не являются хешами содержимого.

Нагрузочный сценарий для штатного k6: `k6 run deploy/load-test.js`. По умолчанию он обращается только к локальному Caddy на 5193; другой адрес задаётся через `BASE_URL`, число загрузчиков — `VUS`, длительность — `DURATION`. Не направлять тест на сторонние службы или ресурсы «Братиков». Локальные результаты не доказывают ёмкость VPS.

На стартовом экране и под офисом есть выбор «3D / Облегчённый». Для прямого запуска без Three.js и GLB добавить `?graphics=lite` или `?demo=1&graphics=lite`; WebGL этому виду не нужен. Сохранённая партия не удаляется при смене вида.

## Проверить локально

```powershell
npm run check
npm test
npm run build
python -m http.server 5180 --bind 127.0.0.1 --directory dist/demo-v05
```

Открыть http://127.0.0.1:5180/ — обычная игра. Адрес http://127.0.0.1:5180/?demo=1 сразу открывает партию с Мирой, Искрой и Эхо. Демо использует отдельное сохранение и не заменяет обычную партию. При первом открытии команда входит в офис и занимает места. Затем: «Раздать задачи» → проверить исполнителей → «Начать смену».

Для полного показа со вступлением открыть корень адреса, нажать «Открыть студию» и пройти три страницы Ники. Затем доступны найм, рассадка, проект, мини-игра и следующий заказ в одной партии. При возвращении в сохранённую обычную игру нажать «Вернуться в студию». Быстрый показ `?demo=1` пропускает начальный найм; история остаётся доступна из подсказки Ники. Голос и музыка запускаются только после действия игрока, выключаются кнопкой звука; голосовые файлы локальные, платных запросов из демки нет.

Сборку можно обновлять при работающем локальном сервере: сборщик очищает содержимое проверенной папки `dist/demo-v05`, сохраняя сам каталог. Версии связанных модулей и новых CSS согласованы, чтобы обновление не смешивалось со старым интерфейсом из кэша.

## Загрузить на сервер

Содержимое `dist/demo-v05/` скопировать в каталог сайта. Готовый локальный архив: `dist/do-reliza-demo-0.5.0.zip`. При распаковке index.html должен оказаться в корне выбранного каталога. Можно разместить в подпапке: все пути относительные. Для быстрого старта добавить `?demo=1` к адресу.

Для повторной упаковки после `npm run build` в PowerShell:

```powershell
Compress-Archive -Path dist/demo-v05/* -DestinationPath dist/do-reliza-demo-0.5.0.zip -Force
```

На сервер нужны только файлы этой сборки. Рабочую папку проекта, .git, work/, исходники Blender и настройки Codex не публиковать. Сборщик копирует игровые модули, assets/ и локальную Three.js с её MIT-лицензией; исходники и локальные логи в сборку не входят.

Стандартный статический сервер должен отдавать .js как JavaScript, .css как CSS. Для index.html предпочтительна повторная проверка кэша; модули и GLB имеют версию в URL. SPA fallback, база данных и Node.js в production не требуются. Доступ посетителей регулируется самим хостингом.

После загрузки проверить обычный вход и `?demo=1`, дождаться рассадки, пройти смену до «Орбиты» и обновить страницу. Не считать локальную проверку подтверждением публикации. Публичный адрес в этой итерации не настроен.

## Управление офисом

- До смены: «Нанять и посадить» назначает свободный компьютер; пересадка доступна в панели команды через списки «Кто за компьютером 1/2/3». Также можно выбрать сотрудника и компьютер или свободный пол прямо в сцене.
- Камера: перетаскивание, колесо или жест; кнопка приближения следит за выбранным персонажем. ⌂ возвращает общий вид.
- Во время смены: сотрудник → «Наблюдать за работой» для крупного плана; «Следующий час» или «Авто» для продвижения проекта. Автоход сохраняет включённый режим при событиях и окнах, продолжает после решения; скрытая вкладка не расходует часы. Текущий час, время показа и остаток постоянно видны сверху.
- Ника: крупный значок справа внизу → подсказка. После 10 секунд без действий появляется мягкое приглашение; оно не открывает окно и не запускает голос автоматически.
- Состояние команды: карточка под офисом → «Перерыв · 1 рабочий час». Сотрудник дойдёт до уголка отдыха, сядет в кресло; затем «Следующий час» восстанавливает силы, он встаёт и возвращается к своему компьютеру. Кресло одно: остальные запросы ждут в очереди, сотрудники пока продолжают работу. Во время дороги часы ждут; «Авто» обслуживает очередь само. На узком экране переключаться между «Студия» и «Смена».
- Кнопка «Офис» открывает кассу и улучшения. Покупки до смены или после релиза меняют обивку кресла и чайный столик, добавляют акустические перегородки и обновлённые корпуса компьютеров. Купленное сохраняется и появляется после обновления старой партии.
- После релиза: следующий заказ с сохранением команды, состояния и улучшений. Обычная и демо-кампания сохраняются раздельно.
- Строительство дополнительных помещений, новые студии и сетевой мультиплеер пока не реализованы.
