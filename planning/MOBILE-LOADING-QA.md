# Загрузка и мобильный вход — 24 октября 2026

## Причина

Предыдущие 2 107,8 мс — p95 HTTP-запросов ассетов при 50 VU, не время запуска игры. В том сценарии p95 ожидания первого байта был 1 485 мс, получения тела — 1 396 мс; эти перцентили нельзя складывать. На VPS локальная выдача занимала около 12 мс для HTML и 17 мс для сжатой модели, CPU/RAM не исчерпаны. Внешний curl нового соединения: TCP 14–74 мс, TLS завершался на 560–710 мс, первый байт на 792–961 мс. HTTP-duration в k6 не включает установление TLS, поэтому задержка сертификата не объясняет весь p95. Chromium договаривается об HTTP/2.

В браузере обнаружены три последовательные волны импорта модулей. Старт делал 25 запросов: семь CSS, приложение и зависимости, повторно office-runtime с другим cache tag. Фон 317 250 байт начинал загружаться только после выполнения JS. Все файлы имели no-cache: повторный вход снова делал 25 проверок по сети.

## Изменение

- Зафиксированный esbuild 0.28.2 объединяет CSS и модули при подготовке публикации. Движок/интерфейс остаются HTML/CSS/JS, исходники по-прежнему открываются через HTTP без сборки. 3D остаётся отдельным динамическим чанком; тест графа запрещает Three.js в стартовой загрузке.
- Фон для ширины до 760 px — 768 px WebP, 61 196 байт (на 81% меньше исходного WebP). Фон предварительно загружается по media; источники сохранены, преобразование штатным ffmpeg отражено в asset-receipt.json.
- Общий assetURL сохраняет адреса моделей/озвучки при объединении модулей и размещении в подпапке. Source cache tags не создают дубликаты singleton-модулей при сборке.
- Вся статическая поставка размещается в static/<хеш всех файлов>/. Эти каталоги immutable на год; HTML и version.json revalidate. Новый релиз использует новый хеш. Caddy хранит старые static-каталоги отдельно от current, чтобы открытая вкладка могла позднее загрузить старые модели/голос.

## Замеры

Источник — Chromium, тот же VPS и HTTPS-домен. Мобильный профиль: 390×844, DPR 3, touch, 1,6 Мбит/с вниз, 0,75 Мбит/с вверх, добавленная задержка 150 мс, CPU ×4. Это эмуляция настольного Chromium, не физический Android/iPhone. FCP — появление содержимого стартового экрана, не готовность 3D.

Три парных прогона старой публичной версии и кандидата на временном /_preview/, отдельный свежий контекст для каждого холодного/повторного входа. Медианы:

| Показатель | До | После |
|---|---:|---:|
| Запросы ресурсов старта | 25 | 5 |
| Передача ресурсов холодного входа, включая HTTP overhead Resource Timing | 412 399 байт | 133 742 байта |
| FCP холодного входа | 2 308 мс | 2 116 мс |
| FCP повторного входа | 1 004 мс | 316 мс |
| Передача ресурсов повторного входа | 7 500 байт | 0 байт |

HTML проверяется по сети в обеих версиях и в число ресурсов таблицы не входит. Первые отдельные прогоны дали 3 684→2 360 мс, но сеть/CPU меняются: для вывода использованы парные медианы выше. Запись результатов — work/loading-ab.json, work/loading-baseline.json, screenshots outputs/playwright/loading-ab-*.png; они локальные, в Git не входят. Это не универсальные SLA.

Обновлённый k6 загружает реальные файлы новой сборки, включая динамический 3D-чанк, фон, портреты и восемь моделей. 50 VU, 10 секунд: 1 500 запросов, 0 ошибок, p95 около 1,66 с. Порог p95<1 с **не пройден**. Ранний неполный сценарий без 3D-чанка/изображений дал 1,09 с; он не используется как итог. Старый сценарий имел 16 файлов, новый 15: это проверка новой поставки, не строгий тест одного неизменного запроса. Кеш браузера k6 не симулирует.

## Функциональная и визуальная проверка

- npm run check; npm test — 49/49 групп, включая 1269 полных сценариев движка. npm run test:hosting — 3/3 проверки графа ленивой загрузки, существования файлов/ссылок и размеров. Повторная сборка дала тот же хеш static, что необходимо для immutable-кеша.
- Реальный Chromium на HTTPS-кандидате: в graphics=lite поставлены два перерыва в очередь, перезагрузка сохранила их; смена пройдена обычными кнопками через решения/случайное событие, результат сохранён после обновления, «Орбита» выиграна стрелками. В lite нет скачивания GLB/3D-чанка. Затем тот же результат открыт в 3D, сотрудники и офис загрузились. Обычная новая игра загружает Alina MP3 по правильному адресу; ошибок страниц и ответов 4xx/5xx нет.
- Ширины 320/768/1024/1440 без горизонтального переполнения. Визуально проверены мобильный и настольный старт, 3D и победа в мини-игре; существующая иерархия/палитра/кнопки сохранены. При принудительном отказе WebGL fallback показывает офис и разблокирует планирование без pageerror.
- Реальный слабый Android/iPhone и мобильный оператор не проверялись. Облегчённый режим доступен до входа и сохраняет всю основную игру. Не заявлять универсальный FPS, поддержку всех телефонов или защиту от любого DDoS.

Технические основания: [esbuild splitting](https://esbuild.github.io/api/#splitting), [Caddy precompressed](https://caddyserver.com/docs/caddyfile/directives/file_server), [версионирование и immutable-кеш](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching). Сам сервер не менялся на более дорогой; покупок, платных API и ресурсов «Братиков» не использовано.
