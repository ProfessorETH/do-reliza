# До релиза — правила совместной разработки

## Сначала прочитать

README.md — запуск и текущее состояние. CASE-CHECK.md — критерии кейса.
COLLABORATION.md — работа с двух компьютеров и разделение задач.
planning/README.md — доска в Codex и правила сохранения её состояния в Git.

## Продукт

- Профессия игрока — тимлид. Аудитория — подростки до 16 лет.
- Сохранить найм трёх агентов по пяти навыкам и выбранную вечернюю студию.
- Текущая версия 0.4 — HTML/CSS/JS без сборки, локальная копия Three.js и модели Blender/GLB. Для игры npm install не нужен.
- Офис и персонажи — настоящие 3D-модели из art/blender/, GLB в assets/models/. office-layout.js должен совпадать с размерами и координатами мебели; проверить путь и посадку после изменений.
- Агенты симулируются движком. Не заявлять реальные LLM или серверные агенты, пока они не реализованы.
- Не переписывать проект на другой стек без отдельной задачи.

## Два компьютера

- У каждого отдельный локальный clone. Не редактировать одну рабочую папку по сетевой шаре.
- Перед изменениями проверить git status, текущую ветку и актуальный origin/main.
- Для каждой задачи создавать отдельную feature-ветку от актуального main. Сохранять чужие и незакоммиченные изменения.
- Согласовать, кто владеет файлами задачи. Особенно app.js, style.css, data.js и engine.js: это общие точки конфликтов.
- Объединять через pull request после проверки. Не делать force-push в main, не сбрасывать чужую ветку.
- Перед завершением запустить npm run check и npm test. Для UI использовать frontend-ui-engineering и frontend-design-review, затем проверить реальный браузер на компьютере и телефоне.
- Не отправлять секреты, локальные логи и случайные файлы. Перед первым push и при подозрительных изменениях запускать gitleaks detect --redact.

## Генерация и оборудование

- Глобальные человеческие правила по ComfyUI и GPU сохраняют приоритет.
- Перед рендерами проверять машины, очередь и бронирования. Не останавливать чужие задания и не выгружать чужие модели.
- Генерация видео — только полный сохранённый SeedHunter_PRIMARY_FrameFable_GUI workflow с проверкой источника и копией до правок; другой метод требует явной инструкции человека. Апскейл и интерполяция могут использовать другие подходящие workflow.
- Не запускать видео или тяжёлый рендер просто для проверки этого веб-проекта.
