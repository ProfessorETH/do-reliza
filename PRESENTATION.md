# «До релиза» — материалы для презентации

Подготовка к утру 25 октября 2026. Этот документ помогает собрать слайды из реализованной игры. Итоговый состав сборки и результаты проверок фиксируются в [протоколе передачи](planning/MORNING-HANDOFF.md).

## С чего начать

- Игра: https://do-reliza.xyz/.
- Быстрый показ с готовой командой: https://do-reliza.xyz/?demo=1.
- Мастерская персонажей: https://do-reliza.xyz/characters.html.
- [Готовые кадры для слайдов](presentation/README.md).
- Репозиторий: https://github.com/ProfessorETH/do-reliza. Доступ участнице уже предоставлен; ссылка на закрытый репозиторий сама по себе не даёт доступ жюри.
- [Запуск и размещение](DEPLOY.md), [критерии кейса](CASE-CHECK.md), [правила карьеры «С нуля»](planning/CAREER.md).

Для локальной копии сначала сохранить собственные изменения, затем перейти на `main` и выполнить `git pull --ff-only`. Обычный просмотр исходников не требует установки пакетов:

```powershell
python -m http.server 5179 --bind 127.0.0.1
```

Открыть http://127.0.0.1:5179/. Для сборки нужны `npm ci` и `npm run build`; детали — в DEPLOY.md. Сохранения привязаны к браузеру и адресу: локальная и публичная игра не разделяют прогресс. Демо использует отдельное сохранение.

## Главная мысль

**«До релиза» — браузерная 3D-игра о профессии тимлида для подростков до 16 лет. Игрок собирает команду, помогает сотрудникам и принимает технические решения, а затем играет в выпущенную командой мини-игру и видит последствия своих решений.**

Основание своей студии связывает проекты в кампанию. Профессиональное ядро — подбор по навыкам, зависимости задач, помощь разработчику, согласование объёма и проверка качества.

## План слайдов

1. **Название и идея.** Один кадр игры и формулировка из раздела «Главная мысль».
2. **Профессия и аудитория.** Что делает тимлид и какие его действия выполняет игрок. Аудитория — до 16 лет; понятность на целевой аудитории ещё нужно оценить.
3. **Игровой цикл.** Команда → задачи → помощь и решения → релиз → проверка результата в «Орбите».
4. **Главная особенность.** Конкретный пример: проверил столкновения — корабль останавливается перед астероидом; пропустил проверку — ошибка проявляется в выпущенной игре.
5. **Живая студия.** 3D-персонажи, работа и отдых, состояние команды, разговоры и улучшения офиса.
6. **Развитие.** Карьера «С нуля», обучение, репутация, новые заказчики и рост до пяти рабочих мест. Отдельно показать, что три миссии действительно различаются.
7. **Технологии и проверка.** Краткая схема ниже; фактические проверки брать из протокола передачи, не складывать исторические числа тестов из разных документов.
8. **Команда и ссылки.** Фактические роли, раскрытие использования ИИ, ссылка/QR на игру и доступный жюри способ получить код.

## Сценарий короткого показа

На 3–5 минут. До выступления один раз пройти его в том же браузере и выбрать нужный звук.

1. Открыть `?demo=1`, дождаться загрузки моделей и рассадки. Повернуть камеру, показать три работающих места.
2. Открыть сотрудника. Показать его навыки, текущее состояние и действие помощи. Объяснить связь выбора исполнителя с задачей.
3. Перейти к плану и начать смену. Включить автоход. Показать одно техническое решение и объяснить его последствие; не расходовать весь показ на ожидание каждого события.
4. На релизе открыть «Орбиту». Показать выпущенный продукт и влияние решений на щит, столкновения либо сохранение.
5. Показать экран следующего заказа и развитие студии. Для длинной карьеры использовать заранее подготовленные кадры, не обещать открыть все улучшения за один заказ.

Полный вход со вступлением и наймом показывать через обычный адрес. Карьеру с маленькой кассой — через новую игру со сложностью «С нуля»: быстрый режим `?demo=1` демонстрирует другую стартовую ситуацию.

Если устройство не справляется с 3D, доступен `?demo=1&graphics=lite`. Он подходит для показа механик, а внешний вид 3D лучше показать подготовленными кадрами. Браузер запускает звук после действия пользователя.

## Стек для технического слайда

| Технология | Роль |
|---|---|
| HTML, CSS, JavaScript / ES-модули | Интерфейс и собственная игровая логика |
| Three.js 0.186.1 / WebGL | Отображение 3D, камера и взаимодействие со сценой |
| Blender и GLB/glTF | Модели, материалы, скелеты и экспорт |
| Собственная навигация A* и IK | Обход мебели и согласование поз с рабочими местами |
| localStorage | Сохранение прогресса в браузере |
| Node.js и встроенный test runner | Проверки логики, сохранений, моделей и анимаций |
| esbuild | Объединение и минимизация производственной сборки; исходники можно смотреть без сборки |
| Статический HTTP(S)-хостинг | Запуск игры по ссылке; игрового сервера и базы данных не требуется |

Выбор подходит компактной браузерной студии: интерфейс и игровую логику можно развивать отдельно от моделей, игра распространяется ссылкой, зависимости поставляются локально. Blender используется при подготовке ассетов; на компьютере игрока он не нужен.

## Команда и использование ИИ

- **ProfessorETH — автор идеи и разработчик игры.** Разработка и интеграция выполнены под его руководством с применением ИИ-инструментов.
- **Подготовка презентации — участница команды, уже подключённая к репозиторию.** В финальные слайды вписать её имя и роль в подготовке презентации.
- ИИ использовался как инструмент разработки, генерации графики и синтеза голосов. Для моделей применялся Hunyuan3D; Blender использовался для подготовки и доработки; озвучка создана в ElevenLabs. Происхождение ассетов и записи параметров хранятся в репозитории.
- Разговоры сотрудников определяются игровой логикой. Реальные LLM и серверные агенты в игру не подключены.

## Границы текущего результата

- Реализована браузерная игра с собственной логикой и интерактивным 3D-офисом. Масштаб «полной Sims» не заявляется.
- Новые рабочие места и развитие офиса уже существуют; свободного строительного редактора, сетевой совместной игры и второй студии пока нет.
- Разные головы, скелеты и анимации существуют; полноценного лицевого рига и физики волос нет.
- Адаптивность проверялась в Chromium с размерами мобильных экранов. Это не подтверждение производительности на всех реальных телефонах.
- Оригинальность и учебная эффективность — цели проекта; оценки жюри и исследования с подростками ещё не получены.

Исторические QA-файлы описывают этапы разработки. Для состояния, которое передаётся утром, использовать [MORNING-HANDOFF](planning/MORNING-HANDOFF.md).
